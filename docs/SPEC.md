# QuickReply — техническое задание v1.1 (исправленное)

Исходное ТЗ остаётся в силе. Ниже — пункты, которые изменены или уточнены по итогам технического ревью. При противоречии этот документ имеет приоритет.

## 0. Формат работы

- Срок «7 дней» заменён на: **MVP за одну рабочую сессию, далее итерации**.
- Text Blaze — только внутренний референс для разработчиков. В листинге Chrome Web Store, на лендинге и в коде продукта сравнения с чужими брендами не используются.
- Продукт — **Chrome-расширение** (Manifest V3), а не Google Workspace Add-on. Работа внутри Google Docs (canvas-рендер) не входит в MVP и явно указывается как ограничение.

## 1. Разрешения (заменяет «минимальные разрешения»)

| Разрешение | Тип | Зачем |
|---|---|---|
| `storage` | обязательное | Локальное хранение шаблонов, папок и настроек (`chrome.storage.local`). |
| Content script на `<all_urls>` | обязательное | Автоподстановка должна работать на любом сайте, где пользователь печатает. Без этого основная функция невозможна. |
| `clipboardRead` | **optional** (`optional_permissions`) | Только для переменной `{clipboard}`. Запрашивается у пользователя в момент включения в настройках, а не при установке. |

- `activeTab` не используется: он требует клика по иконке на каждой вкладке и ломает автоподстановку.
- Background service worker не используется (не нужен для MVP).
- Подробное обоснование для модератора — `docs/PERMISSIONS.md`.

## 2. Механизм срабатывания (уточняет 4.2)

- Shortcut — произвольная строка 2–32 символа без пробелов. Префикс по умолчанию для новых шаблонов настраивается: `/` (по умолчанию), `;`, `//`, `!` или без префикса.
- Причина: `/` конфликтует со slash-командами Slack, Notion, Discord, Linear. Пользователь может выбрать `;`.
- Режимы срабатывания (настройка):
  - **Instant** (по умолчанию): замена сразу при совпадении.
  - **After delimiter**: замена после пробела или знака препинания; разделитель сохраняется.
- Конфликт префиксов (`/hi` и `/hire`): если shortcut является префиксом другого активного shortcut, в режиме Instant он срабатывает только после разделителя.
- Граница слова: shortcut не срабатывает, если перед ним стоит буква или цифра (`site.com/hello` не раскрывается).
- Одинаковые shortcuts запрещены (проверка в редакторе и при импорте).

## 3. Вставка текста (уточняет 4.2)

- **input / textarea**: выделить диапазон shortcut через `setSelectionRange`, затем `document.execCommand('insertText')` — сохраняет undo и генерирует нативные события `input`, что работает с React-controlled полями. Фолбэк: нативный setter `HTMLInputElement.prototype.value` / `HTMLTextAreaElement.prototype.value` + событие `input` с `bubbles: true`.
- **contenteditable** (Gmail и др.): `Selection`/`Range` — расширить выделение назад на длину shortcut (`selection.modify`), затем `execCommand('insertText')`; переносы строк — `insertLineBreak`. `innerHTML` запрещён.
- Защита от рекурсии: флаг реентерабельности на время вставки; события IME-композиции игнорируются.
- Поля с паролями, платёжными данными, одноразовыми кодами (`type=password`, `autocomplete=cc-*`, `one-time-code` и т. п.) не обрабатываются.

## 4. Переменные (уточняет 4.3)

- `{date}`, `{time}`, `{datetime}` — по локали браузера.
- `{clipboard}` — **P1/опционально**: работает только после того, как пользователь включил её в настройках и выдал optional-разрешение `clipboardRead`. Без разрешения подставляется пустая строка, в редакторе показывается предупреждение.
- Любая другая переменная вида `{name}`, `{company}` — поле ручного ввода в компактном окне (закрытый Shadow DOM, только `textContent`).
- `eval`, `new Function` и выполнение пользовательского кода запрещены.

## 5. Тестирование (уточняет раздел 10)

- Unit: Vitest для движка (совпадения, переменные, импорт, валидация).
- Интеграционные: Playwright. Для загрузки расширения нужен `launchPersistentContext` в headed-режиме или new headless Chromium (headless shell расширения не поддерживает).
- Если в окружении нет полноценного Chromium, контент-скрипт и UI тестируются в реальном движке Chromium через шим `chrome.storage`; загрузка расширения целиком проверяется вручную по `docs/MANUAL_TESTING.md`. Отчёт явно разделяет «проверено автоматически» и «требует ручной проверки».

## 6. Лендинг (уточняет раздел 3)

- Next.js с `output: 'export'` — статический экспорт, деплой в Cloudflare Pages без адаптеров. Каталог сборки: `apps/website/out`.

## 7. Монетизация (уточняет раздел 12)

- Лимиты тарифов в код не закладываются как действующие. Есть абстракция `PlanLimits` с единственным значением `unlimited` для Free v1. Платные функции в UI не показываются.
